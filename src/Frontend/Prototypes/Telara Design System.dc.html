Telara Design System

A unified manufacturing operations platform built on Theory of Constraints principles, making station, equipment, and product telemetry visible in real time across every layer of the organization. This document is the working reference for how Telara looks, sounds, and is built — assembled from README.md, OVERVIEW.md, ARCHITECTURE.md, DECISIONS.md, and the three role dashboards. For the machine-readable version Claude Code should read, see DESIGN.md.

Product context

Telara monitors stations, equipment, and sensor telemetry to find the floor's true constraint ("Herbie", after the Theory of Constraints) rather than rewarding local efficiency that just piles up inventory in front of a bottleneck. Six planned service domains: Equipment & Sensor Monitoring, Production & Product Tracking, Station Management, Personnel & Scheduling, Analytics & Reporting, Escalation & Notification.

Frontend is a Blazor WebAssembly "Island" (desktop/laptop) talking to backend services over GraphQL. Backend: .NET 10 microservices, an Internal Functionality MCP Server (deterministic data lookups) and a Claude Haiku MCP Server (linear, high-throughput ingestion/workflow) sit behind the UI today; a stateless orchestrator sequencing tool calls (linear + parallel) in front of both is next sprint's work, ahead of a future Claude Sonnet server for constraint reasoning.

Three role-gated dashboards, all built: Station Supervisor (one line, one shift, station by station — isometric station flow), Shift Manager (multiple lines, one shift, each line as a single unit — constraint-type set diagram and shift handoff), Plant Director (whole facility across shifts and weeks — charts, trends, part table; no isometric view). Role sets the landing route; read access is hierarchical, landing is not.

Content & voice

Tone
Direct, engineering-forward, precise. Written like the person who has to act on the alert, not market it. No exclamation marks, no sparkle.
Vocabulary
TOC terms are load-bearing, not flavor: "Herbie" (the constraint), backlog / surplus, station vs. equipment vs. sensor. Use them precisely — don't soften into generic "issue" or "problem".
Casing
Title Case for page titles and primary actions ("Station Supervisor", "Acknowledge"). Sentence case for body copy and alert descriptions.
Numbers & status
State the delta, not just the alarm: "backlog +41", not "backlog detected". Timestamps in 24h, Space Mono. Em dash for empty/unknown values.

Color

Full swatches, hex values and measured contrast ratios live in Telara Brand Foundations. Summary: same hue (blue 215°, green 155°), different lightness per mode, chosen to clear 7:1 (AAA) against each mode's base. One rule worth carrying into code: #6b6d74 is a rule-and-fill grey only — at 2.73:1 on panel it must never carry text. Labels, eyebrows, axis ticks and hold reasons all use #a7acb5 (6.19:1).

Spacing, radii, motion

Spacing
4px base grid: 0, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80
Radii
2 / 4 / 6px, 999px pill. Mostly sharp — matches the industrial reference imagery, not rounded-card conventions.
Motion
Fades only, 120–320ms, cubic-bezier(0.22,1,0.36,1). No bounces, no slide-ins. Status badges may carry a subtle colored glow, not a scale/bounce.

Iconography

Font Awesome (Free) — well-maintained, broad free tier, CDN-loadable, consistent outline weight across the set. Default size 20–24px inline, color inherits via currentColor. Not yet copied into the project — do that when the first real icon usage lands (nav items, alert severities). No emoji, no unicode glyphs as icons, matching the plant-floor tool tone.
